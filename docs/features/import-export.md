## ① 这是什么

两个方向的能力：

- **导入 .xmind**：把 XMind 做的文件搬进来变成一张 Gmind 脑图。入口在工作台首页的「导入文件」卡（`apps/web/src/pages/WorkspacePage.tsx:871`，点开后走隐藏的文件选择框 `:790`）。只支持 `.xmind` 一种格式（XMind 8 和 XMind 2020+ 两种内部格式都能读，见规则 2）；单文件上限 20MB。文件里存过思维导图分支左右分布的（根扩展 right-number），导入后左右与 XMind 完全一致（规则 4，2026-11-15 轮 5 起）。
- **导出**：两个入口。① 编辑器顶栏「分享」按钮 → 分享弹框「导出」页签五项：XMind `.xmind`、图片 JPG（白底 2×）、Markdown `.md`、CSV `.csv`、Excel `.xlsx`（`apps/web/src/editor/ShareDialog.tsx:126-132`，规则 20）；② 顶栏导出菜单：XMind＋JPG 1x/2x/3x（`apps/web/src/pages/EditorPage.tsx:4387`、`:4410`、`:4422-4430`；2026-11-15 第三波当日 grep——同日加 runXmindExport 闭包致本文件行号顺移）。PNG 透明档 2026-11-15 随需求方裁定退役（口径「我要白底的 jpg」），图片导出统一 JPG 白底。XMind 导出把当前文件的**全部画布**写成一个多 Sheet 文件，文件里带 XMind 软件默认的主题样式（2026-11-15 轮 4 起按画布结构二选一：思维导图画布=曲线连接线主题、逻辑图/组织架构图画布=圆角折线主题，规则 15）、画布上各节点的图片（规则 15 图片写回链路）与思维导图分支的左右分布（根扩展 right-number，2026-11-15 轮 5 起——写回「右侧分支数」，XMind 按其「前 N 支居右」规则解读这个数：前缀布局（左右未交错）逐支一致，非前缀布局（拖拽换侧/兜底交替导入）首开会按计数重排一次，边界见规则 4/④10），XMind 打开能直接用。

导入后降级提示会**逐项点名**哪些东西没搬进来（比如「未导入：图标 2、外框 1」）；全搬进来了就提示「已完整导入」。

## ② 规则（逐条）

1. **两种内部格式都认**：打开 .xmind（zip 包）后，有 `content.json`（XMind 2020+）优先按新格式读，否则读 `content.xml`（XMind 8 旧格式）（`packages/xmind-io/src/index.ts:99-103`，2026-11-15 当日 grep——本轮该文件头部新增 unzipEntries 开口 +5 行，行号自 11-14 批的 94-98 顺移）。XMind 8 的根元素是 `<xmap-content>`，合成夹具历史形状 `<map>` 也兼容（`packages/xmind-io/src/parse-xml.ts:283-289`）。
2. **20MB 上限**：超过直接拒绝，提示「文件大小超过 20MB 上限，请压缩后重试」，文件不会被解析（`apps/web/src/editor/xmind-import.ts:64`、`:149`）。
3. **画布对应关系**：XMind 的每个 Sheet 进来变成 Gmind 的一张画布：第一个 Sheet 进首画布（画布名=Sheet 名，根文本=Sheet 根标题），其余 Sheet 逐个新建画布，画布自己的布局结构也一并带过来（`apps/web/src/editor/xmind-import.ts:262-288`、`:172-175`；2026-11-15 轮 4 当日 grep——v3 分侧头注扩充致本文件 :250 之后行号顺移，同日终审修复批 Minor#1 兜底头注改写再致 :259 之后 +1；多画布能力见 `packages/gmind-core/src/canvas-ops.ts:72`）。反过来导出时全部画布逐个出 Sheet（`apps/web/src/editor/xmind-export.ts:137-147`，终审修复批当日 grep——同批头注扩写致 +4 顺移）。
4. **布局结构三映射**：根节点上声明的布局按三档认——`org.xmind.ui.logic.right`→逻辑图（向右）、`org.xmind.ui.map.*`→思维导图、`org.xmind.ui.org-chart.*`→组织架构图；认不出的值记一条「结构覆盖」降级、画布落默认布局；**非根节点**上的布局声明一律丢弃并逐条计「结构覆盖」（`packages/xmind-io/src/parse-json.ts:123-130`、`:218-220`；XML 侧 `parse-xml.ts:203`、`:308`）。**思维导图画布的根分支分侧规则 v4——忠实还原为主、算法兜底**（2026-11-15 轮 5 分侧忠实还原批，需求方裁定「左右是用户内容不能靠数字猜，分支可拖拽」；v3 及更早的猜测算法沿革见 m4-acceptance §十/§十四）：
    - **主路径=照抄文件存的 right-number**：XMind 把思维导图左右分布存在**根主题扩展** `right-number` 上，语义=attached 文档序**前 N 支居右**。两种内部格式都读：Zen JSON=`root.extensions:[{provider:'org.xmind.ui.map.unbalanced',content:[{name:'right-number',content:'N'}]}]`（`packages/xmind-io/src/parse-json.ts:140-171`、落 sheet `:356`；仅根有效，子主题上的扩展忽略）、XML=`<extensions><extension provider=…><content><right-number>N</right-number>`（`parse-xml.ts:156-172`、落 sheet `:331`）；provider 不对/值非法一律不产键、不计降级。导入 mindmap 画布定侧直读该计数：floor 后 clamp 到 [0, 分支数]（0=全左合法、越界=全右），前 N 支 right、其余 left——存储值照抄，不算不猜（`apps/web/src/editor/xmind-import.ts:239-246` sidesFromRightCount、定侧分支 `:301-311`；行号为终审修复批当日 grep——同批 Minor#1 兜底头注改写致 :259 之后 +1 顺移）。
    - **导出反向写回同一字段**：每张思维导图画布统计「引擎实际渲染的右侧根分支数」写进导出件根扩展 right-number——计数读 core `countRightSideRootChildren`（`packages/gmind-core/src/operations.ts:78-103`，2026-11-15 起导出供 web 用）：持久 side 计数＋**无 side 根子级按文档序 index 0-2 视右**＋墓碑防御，与画布渲染引擎 `packages/engine/src/layout.ts:264`（`persistedSide ?? (i < 3 ? 'right' : 'left')`）精确同口径；写=`apps/web/src/editor/xmind-export.ts:148-161` docToXmindSheets（行号为终审修复批当日 grep——同批头注口径扩写致该文件 :32 之后 +4 顺移） → `packages/xmind-io/src/build.ts:393-404` 落根 extensions。分支左右=写回 right-number（右支计数），计数恒与画布渲染一致；但 XMind 按「**前 N 支居右**」解读这个数——左右是否逐支一致取决于布局是不是「前缀排布」（居右的恰好是文档序前 N 支）：**前缀布局**（从带计数的文件导入、或在 Gmind 没拖拽过换侧的文档）XMind 打开逐支一致；**非前缀布局**（左右交错的文档，来源=①在 Gmind 拖拽换过侧 ②经 v3 兜底交替腿导入的文件）计数仍正确，但 XMind 首次打开会按「前 N 支」重新排一次（不在前 N 的右支，比如第 2、4 支，静默换到另一边），再存再开即稳定——**导出时是否顺手重排成前缀布局，待需求方裁定**（④10，2026-11-15 终审 Important#1 口径如实改写）。
    - **折算口径（T3 评审裁定的正确性修正，T4 执行）**：Gmind 文档里根分支可以没有持久侧别——模板直建不写 side；把分支拖到画布根 core 也有意不写 side（`operations.ts` moveNode 侧别清理只删不写）。引擎此时按 index 0-2 视右渲染，导出计数用同一折算——这类文档（含全缺省模板文档）的导出件与画布渲染一致、往返无损。修正前只数持久 side，模板/混合文档导出计数与渲染脱节、往返有损。自动化背书：`apps/web/src/editor/xmind-export.test.ts:231`（全缺省 5 支→rightCount=3）与 `:247`（混合文档 [–,R,R,L,L]→引擎渲染 [R,R,R,L,L]→3），红→绿留痕。
    - **兜底=算法**（**仅文件未存 right-number 时**使用）：子树权重最大的分支锚定左侧，文档序在它之前的分支全部居右（保持文档序）、它之后的随它居左；锚点落在第一支（右侧为空）时回退「从右起交替」（第 1/3/5…支右、第 2/4/6…支左）（`xmind-import.ts:248-270` balancedSides——v3 原样降为兜底，一字未动）。引擎右列文档序自上而下、左列倒排，视觉顺序与 XMind 一致。
    - **实证与已知异常**：思维导图.xmind 根 right-number=3，与其 XMind 截图（右=分支1/2/3）一致，导入即还原；**Gmind问题汇总.xmind 文件里存 rn=7，但其 XMind 截图右侧 8 支、差一支**——疑 XMind 8 手动拖拽分支后未刷新根扩展计数（存储值确实只有 7），导入忠实按 7 处理；**点名移位分支=按文档序第 8 支「设置」**（rn=7 时前 7 支居右、它从你 XMind 截图的右侧落到 Gmind 左侧，当日读文件核实：文档序=场景/首页/harness使用总结/Ai/筛选/任务看板/协作/设置/文件/分支主题 6 共 10 支）；要与你的 XMind 显示一致，在 XMind 里拖动该分支并重存（强刷计数）后重新导入即可（④10）。**同名双文件指认**（终审 Minor#2 补记）：工作目录 `/Users/guoyue/工作/个人项目/Gmind/Gmind问题汇总.xmind` 才是存 rn=7 的原件（XMind 8 格式 content.xml）；Downloads 下同名文件是旧 Gmind 导出件（无 right-number，导入走兜底算法）——对现象时认准工作目录这份。
    - logic/org 画布侧别无语义不处理（导入 gate `xmind-import.ts:305`、导出 gate `xmind-export.ts:153`——rightCount 即便在文件里也忽略、导出不产键；均为终审修复批当日 grep 顺移后值）。此前 addChild 固定「右侧最多 3 个」配额随 11-14 批替换（10 分支文件右侧只进 3 个的问题）。

7. **图片**：.xmind 里内嵌的图片**会提取上传入库**，挂到对应节点上（2026-11-14 推翻 M4「图片只计数不提取」旧裁定）。规则：格式只收 png/jpg/gif/webp 四种（按文件头魔数判断，`packages/xmind-io/src/index.ts:44-70` sniffImageMime，2026-11-15 当日 grep——本轮该文件头部新增 unzipEntries 开口 +5 行，行号自 11-14 批的 39-65 顺移）；**长边钳到 200px 等比缩小**（与手动传图同规则，`apps/web/src/editor/imageUpload.ts:65-74`）；单张超 10MB 拒传；一张节点只取第一张图，多余图片逐张计入提示；任何一张图失败只丢那张、导入继续（`apps/web/src/editor/xmind-import.ts:313-349`）。图片的四方向槽位（上/下/左/右）跟着源文件的 align 走，缺省挂节点下方（`xmind-import.ts:341`）。

## ③ 特殊情况

- **文件损坏/不是 .xmind**：提示「文件已损坏，无法解析，请检查文件后重试」（zip 打不开、content 格式不对、组装超限都归这句，`apps/web/src/editor/xmind-import.ts:152-159`、`:288-296`）；zip 里既无 content.json 也无 content.xml → 「无法识别的文件格式（仅支持 .xmind），请更换文件后重试」。
- **根主题没有标题**：文件名照用（原文件名去后缀优先，`xmind-import.ts:166-171`）；中心主题文本为空。
- **Sheet 为空**：第一个 Sheet 没根主题=整份损坏；后续 Sheet 没根主题计「空画布」跳过、不中断（`parse-json.ts:306-315`、`parse-xml.ts:293-296`）。
- **图片引用坏了**（zip 里查不到那个文件/格式不在白名单）：该图计「图片」降级、节点照常进来只是没图（`parse-json.ts:160-162`）。
- **概要标签超长**：core 的 setSummary 会拒绝（超 200 字整单拒绝），捕获后计「概要」降级，文档不留残缺条目（`xmind-import.ts:199-210`；校验先于事务，doc 零残缺）。
- **同图多节点引用**：每个引用节点各传一次图、各挂各的 key（`apps/web/src/editor/xmind-import.test.ts:449` 用例钉住的现行行为）。
- **认不出的标记/样式/结构**：一律「丢弃+如实计数」，不猜不硬塞（2026-11-14 需求方裁定：宁可少映射不可歪映射）。
- **任务进度联动**：进度标记写入会联动任务百分比、双向同步（`packages/gmind-core/src/constants.ts:92-108` 注释口径）；所以 XMind 的进度进来后表格/任务面板/筛选直接可用。
- **导入中断**：单张图失败/单枚图标超上限都只丢那一项，其余照常；只有整个文档组装失败（文本超限/树太深）才整体报「文件已损坏」。
