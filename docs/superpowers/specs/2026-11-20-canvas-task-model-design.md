# 画布多人任务规则与体验优化（第一轮）设计

日期：2026-11-20  
状态：需求方已批准

## 一、为什么改

Gmind 的脑图节点同时承担任务。当前固定负责人允许多人，但共享一个 `task.progress`；真正的逐人进度只存在于自定义人员列，并会与负责人共享进度加权成“有效进度”。这使人员可能重复录入，总进度兼具两种身份，脑图、表格、待办和统计可能显示不同结果；人员列整值覆盖还可能让并发更新互相覆盖。

第一轮先把任务规则和编辑器内体验统一，第二轮再接任务中心、统计、筛选、动态和待办汇总。

## 二、目标与不做

目标：

- 固定一名总负责人，多人执行继续使用自定义人员列。
- 任务总进度独立，人员子进度可分别更新且不反推总进度。
- 总进度与状态一致流转，完成时可选同步所有子进度。
- 脑图、表格、任务面板只展示一个整体数字：任务总进度。
- 多人同时更新不同人员子进度时互不覆盖。
- 旧多负责人任务可自动迁移，版本恢复覆盖新任务字段与人员条目。

本轮不做：移动画布任务编辑、统一参与者中心、任务索引重构、我的待办参与人收录、统计与动态改版、待办汇总重设计。

## 三、已确认产品规则

1. 固定负责人列只能有一名总负责人；自定义人员列承担多人执行。
2. `progress` 只表示任务总进度，可独立更新，不属于任何人。
3. 总负责人有可选执行子进度；存在自定义人员时，与其他人员子进度一起展示和参与完成检查。
4. 不展示自动执行总进度；人员子进度与总进度允许不一致。
5. 取消人员比重控件；旧权重只兼容读取，不再影响任何业务规则。
6. 0%=待开始，1～99%=进行中，100%=已完成；阻塞保留当前进度，阻塞中到 100% 则完成。
7. 总进度设为 100% 与状态设为已完成是同一完成动作。有未完成子进度时提供：完成并全部改为 100%、仅完成并保留子进度、取消。
8. 已完成任务重新打开必须明确选择 0～99% 的新进度并清除完成日期，不再自动清零。
9. 父任务默认手动，可逐任务开启自动计算；自动时只递归平均直属真正任务的总进度，普通说明节点不参与。
10. 所有文件编辑者可改总进度、状态和任何人的子进度；viewer/commenter 只读。
11. 脑图使用紧凑人员头像、子进度环和右侧任务总进度；表格与任务面板保持同义。
12. 旧多负责人自动保留当前顺序第一个人为总负责人，其余进入“原负责人”人员列并保留子进度；迁移前保留可恢复版本。

## 四、方案选择

采用“保留人员列，拆分总进度”的兼容演进：

- `ownerId` 是唯一总负责人；`progress` 是任务总进度；`ownerProgress` 是总负责人的可选子进度。
- 人员列从整列普通对象升级为逐用户、逐条目的 Yjs 嵌套结构。
- 共享总进度读取器只处理手动值和父子汇总，不再混合人员进度。
- 完成预检与完成命令分离，完成命令在一个事务内处理总任务和可选子进度。

不采用纯界面换皮，因为无法解决并发、迁移和跨页面口径；不采用统一参与者中心，因为会破坏同一人员在不同人员列承担不同工作的现有语义。

## 五、迁移与恢复

- 旧无人员任务：新总进度保持旧 `progress`。
- 旧有人员任务：新总进度保持迁移前旧有效进度；总负责人子进度取旧原始 `progress`。
- 旧多负责人：第一人成为总负责人，其余进入确定 ID 的“原负责人”人员列，子进度取旧共享进度。
- 旧 done 异常优先保留完成事实，不伪造历史完成日期。
- 迁移确定、幂等、使用 system origin；第二次装载零新增写入。
- 列上限等异常无法完整迁移时中止并提示，禁止丢人。
- 恢复覆盖总负责人、总负责人子进度、总进度、状态、自动开关、日期和自定义人员条目；恢复不弹确认、不自动补全子进度。
- 总任务完成而人员子进度未全是合法状态，repair 不得强制补全。

## 六、界面规则

- 固定负责人单选；没有其他执行人时隐藏重复的总负责人子进度行。
- 脑图左侧为总负责人和人员头像，头像环表示各自子进度；右侧只显示任务总进度。
- 表格内置进度列只显示、排序和编辑任务总进度；人员列只显示逐人子进度。
- 只有真正开启自动计算的父任务显示 Σ 且只读；手动父任务可编辑。
- 折叠只影响可见性，不改变汇总结果。
- 脑图、表格、任务面板共用完成确认和重新打开流程。
- 自动父因全部子任务完成而到 100% 时不弹人员确认、不阻断子任务编辑，保留人员子进度。
- 自动父的总状态随总进度派生；完成日期取最晚直属子任务的有效完成日期，不伪造当天。
- 0% 直接选择进行中时要求补选 1～99% 进度。
- 更换总负责人清除旧负责人子进度但不改总进度；撤销时一起恢复。
- “未分配”只表示没有总负责人，不表示没有人员列参与人。

## 七、第二轮边界

第二轮扩展任务索引到所有画布和全部参与人；我的待办同时收录总负责人与执行人并去重、标角色；区分总负责人和参与人筛选；统计按任务总进度；动态记录可信任务事件，并与待办汇总一起设计。

## 八、验收重点

- 子进度变化不改变总进度，两个客户端更新不同人员不互相覆盖。
- 完成、取消、保留子进度、全部同步、重新打开均有真实浏览器用例。
- 旧多负责人迁移不丢人，迁移幂等，版本恢复完整。
- 脑图、表格、面板在手动父、自动父、折叠和普通说明节点下保持同一总进度。
- viewer/commenter 不可写，手机维持现有简化边界。
