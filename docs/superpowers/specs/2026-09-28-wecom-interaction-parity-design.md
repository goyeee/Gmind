## 二、需求方裁定记录（2026-09-28 本轮）

1. **翻案恢复**：工具栏 上级/子级/同级三按钮、概要+外框工具栏按钮（含**外框功能本身**，2026-09-27 排除清单作废该项）。
2. **维持不做**：关联线、大纲模式（2026-09-27 裁定继续有效）。
3. **画布手势**：空白左拖 = **框选**（与企微一致）；平移改为 空格+左拖 / 中键拖动 / 滚轮（滚轮平移、⌘+滚轮缩放维持现状）。
4. **格式面板**：按企微重构——工具栏「格式」入口 + 右侧抽屉（画布|节点双页签），现有 RichPanel 内容并入节点页。
5. 多画布（企微底部画布页签）、标签（⌘⌥T）：**本期不做**，登记备选。

## 三、改造项设计

### P0-1 空白左拖框选 + 平移改道

- **现状**：空白左拖由 Viewport 平移画布（`packages/engine/src/viewport.ts:229-252`）；框选需 Shift+左拖（`apps/web/src/pages/EditorPage.tsx:1278-1347`）。
- **目标**：
  - 空白左拖（无修饰键）= 框选 marquee（复用现有 selection.ts 矩形相交逻辑）。
  - 平移：空格按下期间左拖（按住 Space 光标变抓手）、鼠标中键拖、滚轮/触控板双指（现状保留）。空格+拖实现于 Viewport 或 EditorPage 指针链路，Space 不再作为"进入编辑"——进入编辑改由 F2/双击/回车（见 P2-4）。
  - Shift+左拖框选保留（惯性兼容，成本为零）。
- **影响面**：viewport.ts 平移触发条件、EditorPage 指针分发、keyboardMap（Space 改绑）、快捷键面板文案、既有 e2e 中"左拖平移"用例迁移。
- **测试**：engine 单测（viewport 平移仅在中键/空格态触发）；web e2e 用 mouse.down/move/up 断言框选选中集合与画布原点不变。

### P0-2 节点拖动：排序落点 + 多选拖动 + 反馈提速

- **现状**：DragController 仅换父，悬停满 300ms 才高亮 `.drop-target`，释放后追加到目标子级末尾（`packages/engine/src/drag.ts:125-178,256-289`）；无同级排序、无插入指示线。
- **目标**：
  - 拖到节点**本体中线区域** = 变其子级（现状语义）；拖到同级两节点**间隙** = 显示**插入指示线**，释放后按落点排序（调 core moveNode 到目标 index）。
  - hover 高亮反馈从 300ms 降至 ~100ms。
  - 多选拖动：拖动已选中节点且选择集 >1 时整组移动。语义定死：**同父多选** = 整组换父或整组排序到同一落点（保持组内相对顺序）；**跨父多选** = 统一换父追加到目标子级末尾（不做排序落点）。
  - 拖到空白 = 移为 root 子级（现状保留）。
- **约束**：core moveNode 已有，排序落点 index 计算放 `withTransaction` 之外（纪律#2）；布局金样不变（仅交互层）。
- **测试**：engine drag 单测（落点分类：子级/前插/后插/禁止）；e2e 拖动排序断言兄弟顺序。

### P0-3 选中节点 ⊕ 快捷按钮

- **现状**：无（全仓无悬浮快捷按钮实现）。
- **目标**：单选节点时，在节点外侧边（左侧分布节点在左、右侧在右，随布局方向）渲染 ⊕ 圆形按钮；点击 = 在该节点下新建子级并进入编辑（复用 openNewNodeEditor）。多选/编辑中/只读态不显示。
- **实现**：SVG 层 `<g data-testid="quick-add-child">`，坐标随 render 布局输出计算；点击事件不触发拖拽（stopPropagation + pointerdown 标记）。
- **测试**：e2e 选中节点→⊕ 可见→点击→出现编辑态新子级。

### P0-4 标记批量应用

- **现状**：`applyMarker` 只写单一 `selectedNodeId`（`MarkerPanel.tsx:112-135`、`EditorPage.tsx:442-450`）。
- **目标**：选择集 >1 时，点标记对**全部选中节点**应用/移除（同组替换、再点移除的语义按组内多数派？——取简：点击即对全组 set；移除以"当前是否全部已含该标记"决定 set/null）。面板高亮态以**主选中节点**（最后点选者）为准。
- **测试**：core 层 markers 批量写单测；e2e 框选 3 节点→点 P1→三节点均含 P1。

### P1-1 格式面板重构（RichPanel → FormatDrawer）

- **现状**：RichPanel 常驻右列，仅填充色/文字色/字号/作用域；无画布级配置、无工具栏入口。
- **目标**：
  - 工具栏加「格式」按钮，开/关右侧抽屉「格式设置」，**画布|节点双页签**（与 MarkerPanel 共用抽屉容器形态，互斥打开）。
  - 节点页：保留现有填充/文字/字号；新增 快速节点样式预设（从 12 主题派生 8 个预设 swatch）、边框类型（无/实线/虚线）+ 圆角档位、「应用到兄弟主题/所有同级主题」按钮；现有备注/链接/图片编辑区保留在节点页下方。
  - 画布页：结构切换（现有 3 结构）、主题入口（打开主题画廊）、画布背景色（随主题，提供 跟随主题/自定义 两态）、分支形状若引擎已支持则暴露，否则仅登记缺口。
  - **不臆造引擎能力**：预设/边框/圆角/背景落库前逐项核对 engine render/themes 是否已有字段；没有的按"engine 只增不改"新增可选字段+金样重生成。
- **测试**：panel 组件单测；e2e 抽屉开合、页签切换、预设应用、应用到兄弟主题。

### P1-2 标记分组补齐

- **现状**：图标页 优先级/进度/旗帜/星标 四组；表情页三类 tab。
- **目标**：图标页补 **心情**（顶置，5 个情绪图标）、**数字**（1-9,0 圆形数字）、**箭头**（左右上下双向 5 个）三组；星标并入保留。数据模型零改动（markers 仍是 string 集合，只扩枚举值与 SVG 资产）。
- **测试**：render 单测新组图标渲染；e2e 每组各应用一个。

### P1-3 工具栏：三按钮 + 概要/外框按钮

- **目标**：工具栏在「插入」后加 上级主题/子主题/同级主题 三按钮（复用现有 Shift+Tab/Tab/Enter 路径，无选中置灰）；「概要」按钮（复用现有 addSummary，要求同父连续兄弟的选择校验与右键菜单一致）；「外框」按钮（见 P1-4）。
- **测试**：e2e 按钮置灰态、点击效果与快捷键等价。

### P1-4 外框（Boundary）新功能

- **企微/XMind 语义**：选中节点 → 添加外框 → 圆角矩形包围该节点**及其子树**；一个节点最多一个外框；外框可选中（点边线）、删除（右键或 Delete）；随布局自动重算包围盒。
- **数据模型**：文档级 `boundaries` 集合（{id, nodeId} 起步，样式字段后续）——属"新文档级数据"，**必须**在 repair/restore 路径与 summaries 同裁定（纪律#7，参照 `packages/gmind-core/src/restore.ts` 头注先例）；写入口走 core 操作 API 新增 `addBoundary/removeBoundary`（纪律#1）；校验（节点存在、无重复外框）在事务外（纪律#2）。
- **渲染**：engine 新增边界层（子树包围盒计算 + 圆角 rect 描边），金样新增字段用 `UPDATE_GOLDENS=1` 重生成并 diff 核对（纪律#5）。
- **协同**：Yjs 文档结构内新 map，远端收敛走 `attachRemoteNormalization` 同路径。
- **导入导出**：XMind 导出映射 `<boundary>`，导入解析（XMind 格式原生支持 boundary）；PNG/JPG 导出自然包含。
- **测试**：core 单测（增删/repair/restore/重复拒绝）；engine 金样；e2e 添加/选中/删除/撤销；XMind 导出断言。

### P2 细节对齐

- **P2-1 主题浮层画廊**：ThemePanel 从抽屉改为工具栏浮层，按分类分组（12 套映射到 默认/商务/多彩 等类）。
- **P2-2 状态栏**：节点计数改为「主题: 选中/总数」（上限文案待节点上限功能，本期只加选中数）。
- **P2-3 工具栏折叠**（⌘F1 收起为单行）：视 P0/P1 工期决定，可顺延。
- **P2-4 编辑入口键位**：F2 = 进入编辑（XMind/企微惯例）；Space 让位给平移抓手（见 P0-1）。

## 四、工程纪律与风险

- 全部写走 core 操作 API；校验/diff 在 `withTransaction` 外。
- engine 只增不改：布局金样仅新增字段，重生成后 diff 核对范围。
- 交互变更会破坏的既有资产：e2e「左拖平移」用例、快捷键面板 Space 文案、keyboardMap 单测——同 PR 迁移。
- UI 一律 `data-testid`；错误文案两段式。
- 外框属新文档级数据，repair/restore/XMind IO 三处口径必须同 PR 落地并登记验收文档。
- 门禁五件套全绿为收口标准。
- SDD 流程：本 spec 评审后走 writing-plans 出实施计划，分批落地（P0 一批、P1 一批、P2 择机），每批独立验收并在 `docs/` 登记。

## 五、明确不做（本期）

关联线、大纲模式（维持 2026-09-27 裁定）、多画布、标签⌘⌥T、暗色模式、结构扩展（双向逻辑图/时间轴/鱼骨等）、节点上限显示、提醒查阅。
